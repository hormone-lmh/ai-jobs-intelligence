## 2. 允许范围（robots.txt 实测）

`https://www.zhipin.com/robots.txt` 返回 200，与本次采集路径相关的原文：

```
User-agent: *
Disallow: /*?query=*
Disallow: /*?city=*
Disallow: /*?experience=*
Disallow: /*?salary=*
Disallow: /*?degree=*
Disallow: /*?key=*
Disallow: /*?page=*
Disallow: /*?*
Disallow: /job_detail/l*.html
```

判定：**不允许**。`Disallow: /*?*` 覆盖全部带查询参数的路径，而搜索、筛选、翻页全部依赖查询参数。

补充：路径式 SEO 页（如 `/zhaopin/<hash>/`）不带查询串、robots 未逐条禁止，但它是搜索引擎的缓存索引，既非当期数据，也不能按城市/关键词重组。不得用它代表"最新岗位"。

## 4. 探测 2：真实窗口 + 首页，并做对照实验（2026-11-11 21:51）

### 4.2 对照实验（关键）

复现：`scripts\diag_multi.py`。同一 Playwright、同一 Chrome，只换站点与 headless 开关：

| 站点 | headless | 状态码 | 加载后 URL | title | body |
|---|---|---|---|---|---|
| example.com | True | 200 | example.com | Example Domain | 1989 |
| example.com | False | 200 | example.com | Example Domain | 1989 |
| zhipin.com | True | 200 | **about:blank** | 空 | **39** |
| zhipin.com | False | 200 | **about:blank** | 空 | **39** |

### 结论

1. **不是工具链问题**。同一套 Playwright 与 Chrome 访问中性站点，两种模式都正常渲染（1989 字节、title 正确）。若为驱动兼容问题，example.com 也会失败。
2. **不是 headless 问题**。目标站在有头与无头两种模式下表现完全一致，均为空页。所以"改成可见窗口就能用"这个假设不成立 —— 这也解释了为什么弹出给你的登录窗口是空白。
3. **不是登录问题**。未跳转登录页、无验证码、无频控文案，是页面被直接置空。
4. 判定：Playwright `launch()` 启动的实例读不到页面内容。

### 4.3 探测 3：普通 Chrome 与 CDP 连接（2026-11-11 22:00 前后）

**A. 用 Chrome 命令行直接打开**（`--remote-debugging-port=9222`，独立临时 profile，不经过 Playwright 启动）：

| 时刻 | title | url |
|---|---|---|
| 7s | BOSS直聘-找工作BOSS直聘直接谈！ | `/chongqing/?seoRefer=index` |
| 15s | 【BOSS直聘注册登录】boss直聘在线注册登录 | `/web/user/?ka=header-login` |
| 轮询 3 次（间隔 12s） | 「重庆招聘」-2026年重庆人才招聘信息 - BOSS直聘 | `/web/geek/jobs` |

结论：**普通 Chrome 访问完全正常**。页面有内容、标题正确，最终稳定在职位列表页。此前"平台封杀浏览器"的判断是错的，予以修正。

**B. 用 `playwright.connect_over_cdp()` 连接同一实例读取**：

| 次数 | 读取结果 |
|---|---|
| 第 1 次（连接后立即读） | URL 仍是 `/web/geek/jobs`，但 `Page.content` 报 "page is navigating and changing the content"，卡片 0 |
| 带 6 秒稳定等待后再读 | URL 变为 `/chongqing/?seoRefer=index`，仍在导航中，卡片 0 |

结论：**一旦被调试器连接，页面就被重置并进入导航循环**，DOM 读不到。触发点是"被接管"本身，与登录状态无关。

### 4.4 修正后的判定

| 路径 | 结果 | 原因 |
|---|---|---|
| Playwright `launch()` + 本机 Chrome 157 | about:blank，39 字符 | 启动/导航兼容问题，或注入被识别 |
| 普通 Chrome 手动访问 | **正常** | 无 |
| Playwright `connect_over_cdp()` | 页面被重置，读不到 | 调试器连接被检测 |

所以"自动抓取"不成立，但不是因为网络、权限或协议，而是：**只要程序接管浏览器，会话就被重置**。继续调参数让接管不被发现，属于规避检测，不纳入本系统。

| 维度 | 状态 |
|---|---|
| protocol（robots） | 不允许（`Disallow: /*?*`） |
| 技术可行（程序接管浏览器） | 不可行（launch 空白 / attach 重置） |
| 人类访问 | 正常（可用，见 §5 的落地方式） |
| 本次结论 | **P0 自动化不可用** |

### 4.5 副作用记录：重复自动化访问触发风控（必须记住的约束）

2026-11-11 22:05 前后，本机 Chrome 访问 `/web/geek/jobs` 被重定向到
`/web/passport/zp/verify.html?callbackUrl=...`，页面为图片点选验证（提示"请选中下图中所有的…"）。

时间线：

| 时刻 | 事件 |
|---|---|
| 21:43 | 第 1 次 Playwright launch（无头）访问搜索页，页面被置空 |
| 21:51 | launch 有头 + 对照实验，共 4 次 |
| 22:00 | 普通 Chrome 访问 `/web/geek/jobs`，**正常**，稳定在职位列表页 |
| 22:01 | 2 次 `connect_over_cdp` attach，每次触发页面重置 |
| 22:05 | 普通 Chrome 再访问同一路径，**被要求安全验证** |

结论：自动化访问即便读不到内容，也会累积风控评分，最终影响**同一环境下的人工访问**。这构成一条独立约束：**验证与测试必须控制次数，不能反复重试**。

处理：该验证由使用者本人在自己的浏览器中完成，属正常使用；程序不代过、不绕过。

## 5. 执行动作（按方案 §1.3 降级规则）

1. `config/sources.yaml`：`zhipin` 置 `enabled: false`、`role: disabled`，`verification` 段固化上述证据。
2. `backend\adapters\zhipin.py`：仅保留接口位，不实现、不启用。
3. 主路径改为"用户自取内容 + 本地解析"：
   - `snapshot_import`：你用自己的浏览器访问后的页面文件（html / txt / pdf）放到 `data/raw/inbox/`
   - `manual_paste`：整页复制文本粘贴，按规则切成多条岗位
   - `file_import`：CSV / XLSX / JSON
4. 不做的事：不研究如何让自动化通过识别（验证码破解、指纹伪装、代理轮换、频率规避）。这类手段成功率不稳定，且与"低频即合规"是两件事，不纳入本系统。

## 6. 对统计口径的影响

采集中断不再是"偶发失败"，而是**常态**。因此：

- `coverage_gap` 不再是异常，而是主路径的固有属性；趋势图上必须显式标注哪些日期是由快照导入覆盖的。
- 每个数据点必须带 `source_channel`（`snapshot` / `manual` / `file`），跨通道的数据不能直接拼成一条趋势线。
- 由于导入是人工触发，**"某日没有数据"绝大多数情况代表"你没导入"，不代表"岗位减少"**。这一点必须写在页面顶部，不是脚注。
