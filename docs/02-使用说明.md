# 使用说明

## 启动与扩展安装

1. 首次运行 `scripts/setup.ps1`，已有虚拟环境时跳过。
2. 运行 `scripts/start.ps1` 在后台启动服务（重复运行会检查现有服务），打开 http://127.0.0.1:8000/ 。
3. 在 Chrome 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）。
4. 打开开发者模式，选择「加载已解压的扩展程序」，选择 `F:\岗位搜集\extension`。
5. 用自己的浏览器正常打开 BOSS 职位列表或详情页。扩展只读取已经渲染的内容并上报本机，不主动翻页。
6. 返回看板点击「刷新数据」。更新扩展代码后，先在扩展管理页重新加载，再刷新招聘页面。

首次弹出本地网络访问提示时，需允许招聘页面向本机服务上报；本机服务必须运行。浏览器限制或站点页面结构变化可能导致上报不可用，此时使用手动正文录入。

## 查看技能需求

默认展示「岗位正文技能提及」，只分析保存的职位职责和任职要求。有列表但无 JD 时显示空状态，这是数据尚不完整，不是没有技能需求。切换「标题与标签技能分布」可查看摘要信息，两种口径不会混算。

输入岗位/公司关键词、精确城市后点击「应用筛选」，或按 Enter。点击技能可筛选关联岗位，列表支持上一页/下一页。顶部总览是全部样本；技能统计和岗位列表跟随搜索与城市筛选。

技能比例的分母不随技能点击改变，防止被筛选成 100%。技能词典会漏掉尚未收录的技能，且不识别“无需 Python”等否定表述，判断具体要求应查看原文。

## 补充或更新正文

在卡片上点击「补充正文」，或直接在页面底部填写 BOSS 职位详情链接。复制该岗位的职责、任职要求，粘贴后保存。正文至少 20 字，最多 100000 字，不要混入推荐职位或公司介绍。

同一岗位的新正文会替换旧正文，并重建正文技能；标题和列表标签依据独立保留。点击「查看正文与技能依据」可看到正文、采集时间和匹配片段。正文先于列表到达时，岗位显示「待列表页补齐」，浏览列表后会补全标题和公司。

## 数据与历史

- `data/jobs.db`：岗位、当前正文、技能证据、上报批次。
- `data/raw/extension/page_*.json`：原始上报，可回放。
- `data/raw/extension/ingest.log`：成功处理的上报日志。
- `POST /api/import/raw`：回放列表与详情原始记录；旧版本不会覆盖较新版本。原始数据含整页文本但没有正文段落的旧详情会被拒绝，不会污染统计。

当前没有历史对比或在招状态核验；最近见到时间不等于平台发布时间。备份数据库前先停止服务，同时备份原始记录。不要把浏览器 profile 或原始数据提交到版本库。

## 故障处理

- 看板提示连接失败：确认服务启动、端口为 8000，重新点击刷新。
- 扩展没有数据：确认已加载扩展、页面确实显示职位卡片或正文；在招聘页面控制台查看 `[jobs-intel]` 日志。失败会退避重试，仅重试本地上报，不向 BOSS 发额外请求。
- 详情无正文：可能 DOM 结构不匹配，直接使用手动录入。
- 端口被占用：关闭此前由自己启动的服务窗口，再启动；不要批量结束其他 Python 进程。
- 薪资为 □：来源数字不可识别，目前不做薪资分析。

## 主要接口

`GET /api/jobs` 支持 q、city、skill、source（jd/summary）、limit、offset，并返回 total。
`GET /api/jobs/{job_key}/detail` 返回正文和技能证据。
`GET /api/stats/skills` 支持 source、q、city，返回 total_jobs（分母）、sampled_jobs（样本数）。
`GET /api/stats/overview` 返回总览及 jd_jobs。
`POST /api/import/jd` 接收 url、jd_text。
`POST /api/ingest/page` 接收扩展上报。
完整接口见 http://127.0.0.1:8000/docs 。

## 公司视图与需求对比

顶部工作区可以切换「岗位与技能」「招聘公司」「需求对比」。公司视图支持公司名称搜索和城市精确过滤；每张卡片提供岗位数、有正文的岗位数、最近见到时间和正文技能。点击「查看该公司岗位」会切回岗位页，按公司全名精确筛选。

需求对比输入 A、B 两组条件：关键词仅匹配岗位标题，城市与公司精确匹配。留空表示不限制。技能提及率分别以各组有正文的岗位数为分母；差值是 A 减 B 的百分点，而非增长率。某组无正文时比例为缺失，差值为不可比较。学历/经验分布使用各组全部岗位数，保留“未记录”。两组可以重叠，页面会显示重叠数量。小于 30 条正文只是探索性提示，不是统计显著性的阈值。


## 浏览器提示连接被拒绝

本地页面必须由服务提供；电脑重启后需重新启动。运行 `pwsh -ExecutionPolicy Bypass -File F:\岗位搜集\scripts\start.ps1`，看到“已启动”或“服务已运行”后刷新页面。启动脚本验证健康接口与首页，日志保存在 `data/logs/server-*.log`。后台服务不依赖终端窗口保持打开。

## 主页城市筛选

在「岗位与技能」工作区的「城市筛选」中输入或选择城市，候选项来自已采集岗位并显示全库样本数量。选择城市后，岗位列表和技能统计自动筛选，分页回到第一页；点击「全部」恢复所有城市，保留岗位关键词与公司条件。顶部总览仍为全库数据。未记录城市的岗位仅在不限制城市时出现。

## 页面布局与快捷操作

桌面端通过左侧导航切换岗位、公司和对比工作区；手机端导航显示在顶部。总览始终为全库样本，正文覆盖卡片增加进度条。

筛选区会显示已应用的关键词、城市与公司条件。点击条件标签可单独清除，点击「重置筛选」可清除搜索、城市、公司及技能条件（保留当前分析依据）。顶部「＋ 补充正文」可从任意工作区返回正文录入位置。岗位卡片分别标识「正文已收录」与「待补充正文」。
